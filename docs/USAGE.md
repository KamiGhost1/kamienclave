# kamienclave — использование и справочник

Практический справочник по языку payload, host-API и CLI обоих бинарников.
Подъём с нуля — в [SETUP.md](SETUP.md).

---

## Язык payload

Payload пишется на **подмножестве JavaScript**, которое серверный компилятор
(`internal/serverkit/jsbc`) транслирует в bytecode. Поддерживается практичное
императивное ядро; всё за его пределами компилятор отвергает с понятной ошибкой
(а не молча искажает семантику).

### Поддерживается

| Категория        | Конструкции                                                        |
| ---------------- | ------------------------------------------------------------------ |
| Объявления       | `var` / `let` / `const` (по простому идентификатору)               |
| Литералы         | число, строка, `true`/`false`, `null`                              |
| Арифметика       | `+ - * / %`, унарные `-` и `!`, конкатенация строк через `+`       |
| Присваивание     | `=`, составные `+= -= *= /= %=`, `++` / `--` (пре- и постфикс)     |
| Сравнения        | `< <= > >= == != === !==` (строгие, без приведения типов)          |
| Логика           | `&& ||` с короткой схемой, тернарник `?:`                          |
| Поток управления | `if/else`, `while`, `for`, `break`, `continue`, блоки `{}`         |
| Массивы          | литералы `[..]`, `arr[i]` (чтение/запись, рост при записи), `.length` |
| Объекты          | литералы `{k: v}` (shorthand, computed-ключи), `obj.prop`, `obj["k"]` |
| Строки           | индексация `s[i]`, `.length`                                       |
| Завершение       | значение последнего выражения = результат, видимый клиенту         |

### Не поддерживается (отвергается)

`function` / замыкания, `get`/`set`/методы, `for-in`/`for-of`, `try`/`catch`,
прототипы, методы массивов/объектов (`.push` и т.п.), labelled `break`/`continue`,
битовые операции и составное присваивание по индексу/члену.

> Завершающего `return` нет (в подмножестве нет функций). Результат программы —
> значение последнего выражения-стейтмента. Пример: `var x = 6; x * 7` → `42`.

### Host-функции (whitelist)

Payload видит **только** явно разрешённые функции — deny-by-default
(TECHNICAL §7.2.1). Стандартный набор v1:

| Вызов            | Семантика                                              |
| ---------------- | ------------------------------------------------------ |
| `log(...args)`   | диагностический вывод; в backend — без утечки в stdout |
| `env.get(key)`   | значение из whitelist'а env, иначе пустая строка       |
| `sleep(ms)`      | задержка, ограниченная сверху                          |

Сетевых, файловых, `eval`, `require` примитивов нет. Новые host-функции
добавляются только под реальную потребность и за явным whitelist'ом.

### Примеры payload

```js
// 1. Скалярный расчёт
var price = 100;
var discounted = price * (1 - 0.15);
discounted            // -> 85
```

```js
// 2. Массивы и цикл
var xs = [3, 4, 5];
var sumSq = 0;
for (var i = 0; i < xs.length; i++) { sumSq += xs[i] * xs[i]; }
sumSq                 // -> 50
```

```js
// 3. Объект, ветвление, host-вызов
var user = { name: env.get("WHO"), tier: 2 };
var bonus = user.tier >= 2 ? 1000 : 0;
log("bonus for", user.name, "=", bonus);
bonus
```

## CLI: `enclave` / `enclave-vm` (клиент)

Оба бинарника — один и тот же CLI; различаются build-тегом (`enclave-vm`
собран с `-tags backend`: bytecode mini-VM + hardening + silent-exit policy).

### `run` — основной режим

Распаковать лицензию, сходить на сервер, исполнить payload в памяти.

```bash
enclave-vm run --license-file <bundle.lic> [флаги]
```

| Флаг                  | Назначение                                                   |
| --------------------- | ------------------------------------------------------------ |
| `--license-file PATH` | путь к запечатанному бандлу (иначе берётся вшитый, если есть) |
| `--ca PATH`           | доп. CA (PEM) — для самоподписанного сервера                 |
| `--insecure-no-pin`   | пропустить SPKI-пин (только dev)                             |
| `--insecure-no-cert`  | пропустить проверку TLS-цепочки (только dev)                 |
| `-t, --timeout`       | общий таймаут (по умолчанию 30s)                             |

Passphrase запрашивается интерактивно либо берётся из `ENCLAVE_PASSPHRASE`.

### `local` — dev-прогон без сервера

Исполнить локальный JS-файл в том же runtime (только public-сборка, для отладки):

```bash
enclave local --file payload.js
```

### `version`

```bash
enclave-vm version    # печатает версию, вариант (public/backend) и policy-режим
```

## CLI: `enclave-server` (сервер)

| Команда                    | Назначение                                          |
| -------------------------- | --------------------------------------------------- |
| `keygen`                   | сгенерировать пару ключей подписи сервера           |
| `serve`                    | запустить HTTPS endpoint `/v1/fetch`                |
| `license issue`            | выпустить лицензию + записать клиентский бандл       |
| `license list`             | список лицензий                                      |
| `license revoke`           | отозвать лицензию (kill-switch)                      |
| `license attribute`        | восстановить отпечаток из утёкшего fullapp-бандла    |

Ключевые флаги `license issue`: `--id`, `--server-url`, `--server-pub`,
`--cert` (для SPKI-пина), `--payload`, `--out`, `--passphrase`,
`--expires-days`, `--max-concurrent`. Полный пример — в [SETUP.md](SETUP.md).

`serve` поддерживает per-IP rate-limit (срабатывает до проверки крипты):
`--rate` (req/sec, дефолт 5) и `--rate-burst` (дефолт 15).

Наблюдаемость: `GET /metrics` (Prometheus text) — счётчики `enclave_fetch_total`,
`enclave_fetch_ok_total`, `enclave_blob_served_total`, `enclave_rate_limited_total`,
`enclave_fetch_rejected_total{status="..."}`. `GET /healthz` — liveness.

## Протокол (вкратце)

`POST /v1/fetch`: клиент шлёт подписанный (Ed25519) запрос с эфемерным X25519
ключом, nonce и ts. Сервер проверяет подпись, freshness (nonce+ts), статус
лицензии и concurrency-лимит; компилирует payload → watermark → шифрует
(ChaCha20 пул констант + AES-256-GCM на сессионном ключе из ECDH+HKDF);
подписывает ответ. Клиент проверяет подпись и SPKI-пин, расшифровывает,
декодирует bytecode по своей opcode-таблице и константному ключу (из бандла) и
исполняет в mini-VM. Подробности — TECHNICAL §5–§8.

## Типичные ошибки

| Симптом                                  | Причина / решение                                              |
| ---------------------------------------- | -------------------------------------------------------------- |
| `fetch: ... 401`                         | неверная подпись/лицензия не найдена/replay — проверьте бандл и время |
| `fetch: ... 403`                         | лицензия отозвана или истекла                                  |
| `fetch: ... 429`                         | превышен `--max-concurrent` для лицензии                       |
| `server signature invalid`              | `server.pub` в лицензии не соответствует ключу сервера         |
| ошибка SPKI-пина                         | TLS-сертификат сменился после выпуска лицензии — перевыпустите  |
| `jsbc: unsupported ...` при `issue`      | payload использует конструкцию вне подмножества (см. выше)     |
| backend-бинарь молча завершается (exit 0)| сработал hardening: отладчик / нарушение integrity-трейлера    |
